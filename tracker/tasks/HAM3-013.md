## Outcome

Make task hierarchy legible and navigable at real scale, without the tree becoming the thing the owner manages instead of the work.

## Scope

- Move the task list into a full-width main-pane outliner. The sidebar holds projects only.
- Expandable and collapsible rows with a chevron, children collapsed by default.
- A child count badge on every collapsed parent.
- Focus: selecting a task makes it the temporary root, with a breadcrumb back to the full list.
- Row metadata visible without opening the task: at minimum title and status.
- Permit arbitrary practical nesting depth while rejecting parent cycles.
- Make archived task rows explicit and unmistakable when archived items are shown.
- Give the status control, Focus, + child, and Archive distinct, higher-contrast visual roles.

## Non-scope

- Schema changes. `parent_task_id` already permits arbitrary depth. Do not add a migration.
- Drag and drop reordering, keyboard tree navigation, multi-select, or bulk edit.
- List virtualization. Deferred until a project exceeds a few hundred rows.
- Instruction injection, directory bindings, evidence approval, or Git integration.
- Changing the statuses, validation, or persistence delivered by HAM3-004.

## Acceptance

- A project with nested tasks renders as an indented outliner in the main pane.
- Collapsed parents show an accurate child count; expanding reveals exactly those children.
- Focusing a task shows only that task and its descendants, and the breadcrumb returns to the full list.
- A task can be created and rendered at least four levels deep, while self-parenting and ancestor/descendant cycles remain rejected.
- Archived rows have an explicit textual archived indicator plus distinct row treatment; the distinction does not depend on color alone.
- Status, Focus, + child, and Archive controls are readable and visually distinct by function, including hover, keyboard-focus, and disabled states where applicable.
- Collapse and focus state do not corrupt or reorder stored data.
- HAM3-004 behaviour is not regressed: statuses, cycle rejection, comments, and persistence across restart all still work.

## Human check

Owner creates a project with several parents and subtasks, including using the ordinary `+ child` flow twice on the same selected parent and then nesting to at least four levels. The owner collapses and expands multiple depths, focuses into a deep task and returns through the breadcrumb, confirms a cycle is still rejected, enables archived items and can identify archived rows immediately without relying on color, verifies that each row control is readable and visually communicates its function, and confirms after a cold restart that task data is unchanged.
