# HAM3-010 — Exact-SHA evidence and approval workflow

State: `in_design`  
Worker: Anthropic / Claude Code / Claude Sonnet (planning default; bind at dispatch)  
Auditor: Kilo Code / DeepSeek V4 Pro  
Depends on: HAM3-004

## Outcome

Present the strict SHA workflow without authenticating to or controlling GitHub.

## Scope

- Structured worker report, audit report, correction, validation, merge, and shipped evidence.
- Issue/PR/report URLs entered or pasted from agent returns.
- Current head SHA and reviewed SHA comparison.
- Current, stale, changes-requested, validation-pending, merged, and shipped presentation.
- Cross-provider worker/auditor check.
- Manual evidence correction with activity history.
- Readiness summary derived from entered evidence.

## Non-scope

GitHub API, CLI auth, webhooks, automatic refresh, check execution, merge automation, or branch protection.

## Acceptance

- Any new head SHA visibly invalidates previous approval.
- Approval requires a different provider family and exact matching reviewed SHA.
- Infrastructure-flake classification cannot silently become product approval.
- Merged and shipped require explicit observations.
- Readiness explains every missing or stale item.

## Human check

Owner records worker SHA A, approval A, correction SHA B, sees A become stale, then records approval B.
