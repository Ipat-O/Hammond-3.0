# HAM3-002 — Supabase project memory and owner access

State: `in_design`  
Worker: OpenAI / Luna  
Auditor: Kilo Code / DeepSeek V4 Pro  
Depends on: HAM3-001

## Outcome

Provide the minimal Supabase persistence layer for a single persistent owner and all core Hammond records.

## Scope

- Configure local and hosted Supabase environments without committing secrets.
- Add schema for projects, tasks, relations, comments, instruction templates/versions, project selections, task evidence, and activity.
- Add indexes, constraints, timestamps, and owner-scoped RLS.
- Add one-time owner setup and persisted desktop Supabase session.
- Provide typed data access and migration workflow.
- Seed the six base role/provider template categories without product prose lock-in.

## Non-scope

GitHub auth, teams, invitations, organization roles, local path storage, realtime collaboration, or complex authorization.

## Acceptance

- The owner can sign in once and reopen the app without repeated setup.
- A second identity cannot read the owner's records.
- Absolute local paths never enter Supabase.
- Schema creation, reset, and typed-client generation are documented and tested.
- Public-schema tables have explicit RLS and least-required grants.

## Human check

Owner completes setup, restarts Hammond, and sees the same seed project memory.
