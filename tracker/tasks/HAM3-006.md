# HAM3-006 — Harness adapters and managed-file injection

State: `ready_for_development`  
Worker: Anthropic / Claude Code / Claude Sonnet 5  
Auditor: Kilo Code / DeepSeek V4 Pro  
Depends on: HAM3-003, HAM3-005

## Outcome

Write the selected composed instructions directly into a local directory through simple harness adapters.

## Scope

- Persist one explicit execution-provider assignment per project and role (orchestrator, worker, auditor), separate from provider-specific instruction variants.
- Adapter contract for Codex, Claude Code, and Kilo Code.
- Resolve the assigned execution provider to the correct harness adapter and selected effective instruction composition.
- Verified entry-point filename/configuration for each harness.
- Hammond managed-file header and ownership detection.
- Preview, inject, update, and remove operations.
- Replace the previous managed document when role/provider/version changes.
- Conflict UI contract for pre-existing unmanaged target files.
- Optional local exclusion through `.git/info/exclude`.
- Ordinary temporary-sibling replacement and direct filesystem errors.

## Non-scope

Automatic provider scoring/routing, model recommendation, per-session assignment, bridge operations, tokens, manifests, leases, outboxes, provider process launch, Git commands, or silent overwrite of user files.

## Acceptance

- Each project clearly records which execution provider performs each role without changing or hiding the provider-specific instruction variants.
- Each harness receives exactly one correct managed entry-point document.
- Switching selection updates/replaces content and leaves no Hammond duplicates.
- Unmanaged files are never overwritten without owner choice.
- Failure is immediate and names the target/action without indefinite polling.
- Removal touches only Hammond-managed content.

## Human check

Owner injects each harness, changes worker to auditor, restores a version, and verifies files in Explorer.
