## Scope

### 1. Task relationships and blockers

- Add and remove project-scoped `blocks / blocked by` and `related to` relationships from task details, with navigation to the linked task.
- Show unresolved blockers clearly in task details and offer a blocked-task filter. Blockers inform the owner; they do not enforce approval or automatically change status.
- Reject self-links, duplicates, cross-project links, and cycles in blocking relationships. Ordinary related-task links may form cycles.
- Keep relationships separate from the existing parent/child hierarchy. Preserve the HAM3-013 outliner and HAM3-008 navigation/save behavior.
- Define completed blockers using the existing merged/shipped statuses. Archived blockers remain visible as archived references rather than silently counting as completed.

### 2. Links and reference material

- Add labeled web links to projects and tasks; edit, remove, and open them.
- Support attachment references as labeled URLs with optional notes. No file upload or binary storage in this task.
- PRs and reports may be ordinary links or comment text; they carry no structured verdict, SHA, or readiness semantics.

### 3. Project and task activity

- Provide a chronological project timeline and a task-specific view covering durable task edits, status/hierarchy changes, comments, relations, references, and archive/restore actions.
- Show what changed, the affected task/project, and when; link to the affected record when available.
- Record successful durable changes once. Failed saves and retries must not produce misleading success entries or duplicate events.
- Paginate with stable ordering; loading more must not lose or repeat events. Selection, typing, expanding a node, and other transient UI actions are not activity.
- Existing records remain usable without fabricated historical events; history starts where recorded evidence exists.

### 4. Search and filters

- Search within the selected project across task titles/descriptions, comments, and labeled links/reference notes.
- Results show the matching text, record type, and task context and navigate to the relevant record.
- Combine text search with status, blocked/unblocked, and active/archived filters. Default to active items and make archived inclusion explicit.
- Search covers the whole matching dataset, not only already-loaded rows. Empty, loading, failed, and no-match states are distinguishable.

### 5. Board and list views

- Add a status-column board and a compact task list alongside the existing hierarchy outliner.
- Reuse the same task records, details editor, selection, and save behavior across views. Display parent context for nested tasks.
- Apply search and filters consistently across views. Status changes use existing save controls; drag-and-drop is optional, not an acceptance requirement.
- Switching views or projects must preserve existing draft safeguards and must not write a change to the wrong task.

### 6. Project archive and portable export

- Archive and restore a project without deleting its tasks, comments, relationships, or history. Archived projects are hidden from the default project list and accessible through an explicit filter.
- Export the selected project's durable memory as readable Markdown and versioned JSON: project/task fields and hierarchy, comments, relations, references, available activity, and project instruction selections/versions needed to interpret them.
- Export includes archived records with their archive markers and covers all pages independently of current search/view filters.
- Use stable IDs and timestamps in JSON. Markdown keeps task hierarchy and references understandable outside Hammond.
- Omit device-local directory bindings, absolute paths, credentials, and local settings. Document how free-text content and URLs are sanitized; test representative path/secret cases without promising detection of every arbitrary secret an owner could paste.
- Report export failure clearly; a partial export must not appear complete. Import/restore from export is deferred.

## Non-scope

Work-order entry/generation, structured worker/auditor reports, SHA approval/readiness workflow, Git synchronization, provider transcript storage, binary attachment uploads, export import, multi-user collaboration, notifications, scheduling, or complex analytics.

## Acceptance

- Relations enforce the rules above and blocker indicators update after the linked task changes or is restored.
- Search/filter combinations return understandable, project-scoped results beyond the first loaded page.
- Board, list, and outliner show consistent persisted task state after edits, navigation, failures, and restart.
- Activity reflects successful meaningful changes once and paginates without omissions or duplicates.
- Project archive/restore preserves content and does not leak selection or results into another project.
- Both exports contain the complete documented project dataset, including archived records, with explicit privacy exclusions and readable/versioned structure.
- Existing hierarchy, directory switching, instruction editing, and draft/save safeguards continue to work.
